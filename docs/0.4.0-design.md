# FxSound for Linux 0.4.0 — design record

This is the contract the 0.4.0 work was built against. It names every type, message and
setting the release adds or changes at a crate boundary, so that work in `fxsound-core`,
`fxsound-dsp`, `fxsound-preset`, `fxsound-audio`, `fxsound-ui` and `fxsound-app` could proceed
in parallel and still fit together. Where a number is a design choice rather than a
measurement, it says so.

The twelve items of the 0.4.0 roadmap:

1. Output and Input at the same time (both node pairs, both defaults, both chains).
2. Denoiser channel mode: Mono / Linked stereo / Independent.
3. Noise suppression level: Off / Light / Medium / Strong, as a control surface over RNNoise.
4. An `AudioProcessor` trait; the voice chain becomes a list of stages built from a spec.
5. Telemetry in the window: noise floor, voice probability, current reduction.
6. De-esser: Classic / Adaptive (band chosen relative to the source's bandwidth).
7. Echo cancellation through PipeWire's `module-echo-cancel` (WebRTC), VAD into the gate, and a
   light de-reverb stage.
8. Microphone calibration wizard.
9. D-Bus API `org.fxsound.FxSound`.
10. `fxsound --watch [--json]` event stream.
11. CI that builds, installs and self-tests every package; `fxsound --self-test`.
12. Dependency upgrade (egui/eframe 0.36.2, signal-hook 0.4, clap 4.6.7).

Plus: more tests, bug fixes found in the 0.3.0 audit, idle-CPU work.

---

## 1. Two lanes: simultaneous Output and Input

### 1.1 Vocabulary

A **lane** is one direction's worth of engine state: its pair of PipeWire nodes, its DSP, its
ring, its counters, its selection memory and its claim on the session default. 0.3.0 had one
lane that changed direction; 0.4.0 has two, `PerDirection<Lane>`, and each can be **enabled**
or **detached** independently.

- Output lane: `fxsound_sink` + `fxsound_output`, runs `DspEngine` (the music chain). Enabled
  by default at start (the Windows behaviour).
- Input lane: `fxsound_capture` + `fxsound_source`, runs `InputEngine` (the voice chain).
  Enabled only when the user picks a microphone (or the settings file says it was enabled).

The **edit direction** (`Settings.device_direction`, kept under its old key name) is which
chain the window's preset picker, equalizer, level controls and meters address. It is a GUI
concern only; the engine has no notion of it.

### 1.3 `fxsound-audio` changes

- `Shared.lanes: PerDirection<Lane>`; `Shared.direction` is gone. `Lane { enabled, nodes:
  Option<Nodes>, dsp: Option<LaneDsp>, recycle: (Sender<LaneDsp>, Receiver<LaneDsp>), ring:
  Arc<SampleRing>, counters: Arc<Counters>, status: Arc<StreamStatus>, previous_names,
  want_default, needs_rules, attempts, next_attempt, format_mismatches_total, last_status,
  last_sink_cycles, last_underruns, last_error, attached: Option<String> }`.
- `LaneDsp` is an enum `{ Output(OutputDsp), Input(InputDsp) }` with `set_format`,
  `set_layout`, `set_source_rate`, `latency_frames`, `reset`, `refresh`, `process_bytes`,
  `meters`. Each holds its own `Output<Params>`, `Input<Meters>`, `Receiver<DspEvent>` and
  scratch. `SinkDsp` and every `match self.direction` inside it are gone.
- `Config` and `EngineHandle` carry `PerDirection<Input<Meters>>` / `PerDirection<Output<Meters>>`
  and `PerDirection<Receiver<DspEvent>>` / `PerDirection<Sender<DspEvent>>`.
  `EngineHandle::meters(direction)`, `send_event(direction, event)`.
- `apply_rules(shared, direction)`, `claim_default(shared, direction)`,
  `teardown_nodes(shared, direction)`, `drop_nodes(shared, direction)`, `build_nodes` reads the
  lane of `target.direction`. `switch_direction` is deleted. The supervisor runs the error /
  mismatch / rules / latency / publish steps per lane; a NODE 1 error drops that lane's nodes
  and retries with the lane's own backoff (200 ms → 5 s) instead of disconnecting the socket.
- `handle_control(SelectDevice)` calls `apply_rules` for that lane immediately (no 200 ms gap).
  `DetachLane` = `teardown_nodes` + `enabled = false` + `Attached { None }`.
- `on_global` / `on_global_remove` / `on_metadata_property` set `lanes[device.direction]
  .needs_rules`.
- `publish` sends `Status { direction, .. }` per lane when it changed, `Attached` when the target
  changed.
- Bugs fixed here: the `already` check compares channels and rate too; a failed `build_nodes`
  sets `needs_rules` with backoff; `node_probes` is cleared on connect/disconnect; the
  `settings` metadata listener is kept alive so `clock.rate` arrives; `on_sink_format` no longer
  reconfigures the ring under a running NODE 2 (a changed channel count is treated as a format
  mismatch and rebuilt); `on_node_info` accepts a later channel-count change.
- Idle CPU: NODE 2 of the output lane is `set_active(false)` when NODE 1 reports `Paused` (its
  last client unlinked and WirePlumber suspended the sink) and `set_active(true)` when NODE 1
  reports `Streaming`; the ring re-primes on its own. The input lane is left running.
- `AudioStatus.processing` for the input lane is true while the capture stream delivers
  non-silent buffers.

## 2 & 3. Denoiser: channel modes and suppression levels

`nnnoiseless` 0.5.2 is **vendored** into `crates/fxsound-rnnoise` (BSD-3-Clause, `COPYING`
kept; the `weights.rnn` model comes with it; `bin`, `train`, `capi`, `dasp` features and the
`signal`/`training`/`capi`/`nnnoiseless.rs` files are dropped). Reasons, in order: the band
gains `g[22]` are a stack local in `process_frame` and a linked-stereo mask needs them; there is
no in-place `reset()` and the 0.3.0 `Denoiser::reset` therefore rebuilt eight network states on
the PipeWire RT thread on every preset change (an allocation on the audio thread); the library's
own 480-sample synthesis delay was not counted in the reported latency.

Vendored API additions (`fxsound_rnnoise::DenoiseState`):

```rust
pub fn reset(&mut self);                                        // zero GRU states, features, pitch memory; no allocation
pub fn analyse(&mut self, input: &[f32]) -> Analysis;           // shift+filter input, features, RNN, pitch filter:
                                                                //   returns { vad, silence, gains: [f32; 22] } and leaves x/p ready
pub fn synthesise(&mut self, gains: &[f32; 22], output: &mut [f32]);   // apply (possibly edited) band gains and OLA
pub fn process_frame(&mut self, out, in) -> f32;                // = analyse + synthesise, unchanged behaviour
pub struct Stft;                                                // per-channel analysis/synthesis without the network:
impl Stft { pub fn new() -> Self; pub fn reset(&mut self); pub fn push(&mut self, input: &[f32]);
            pub fn synthesise(&mut self, gains: &[f32; 22], output: &mut [f32]); }
```

`Denoiser` (`fxsound-dsp/src/input/denoise.rs`):

- `set_level(DenoiseLevel)`, `set_channels(DenoiseChannelMode)`, `set_control(DenoiseControl)`.
  `is_active()` = enabled && level != Off && 48 kHz.
- **Independent**: one `DenoiseState` per channel (as 0.3.0).
- **Mono**: downmix (mean) → one state → the same output to every channel.
- **Linked**: downmix → one state's `analyse` → the 22 gains, edited by the control surface,
  are applied to each channel through that channel's own `Stft` (`push` + `synthesise`). The
  pitch filter runs only on the analysis path (documented trade-off; the mask carries the
  suppression). Channels beyond the first two share the first two's gains pairwise.
- Control surface, applied to `gains` before synthesis, in this order: `g = max(g, floor)` where
  `floor = 10^(−max_suppression_db/20)`; if `vad < vad_threshold`, `g *= a` where `a` is a
  one-pole smoothed attenuation toward `floor` (time constant 50 ms); `g += voice_preservation ·
  vad · (1 − g)`; then wet/dry: `out = dry_delayed·(1 − w) + wet·w` with the dry path delayed by
  the library's 480 samples so the two are time-aligned.
- Telemetry: `reduction_db()` = smoothed `20·log10(rms_in / rms_out)` per frame, and
  `latency_frames()` = 960 when active (bridge 480 + library 480; pinned by a cross-correlation
  test).
- `reset()` is in place; `set_enabled` / `set_level` / `set_control` never restart the bridge: a
  snapshot that re-applies `enabled = true` while running, a level change, and a toggle undone
  before the next block all cost nothing (0.3.0 restarted on every one of them). The one
  transition that does cost is off→on after the stage has actually stood aside for a block: it
  re-primes from silence and the first 960 frames out are empty. **Accepted, not a leftover.** An
  inactive stage has no latency and an active one has 960 frames of it, so switching on has to
  insert 960 frames of *something*; keeping the bridge and the network running while off would
  fill them with the last 20 ms already heard undelayed — a repeat, which is a stutter, where a
  gap that short is at worst a click — at the network's full CPU cost on every chain that has it
  off, which is the common case and §12's concern. Pinned by tests in both directions
  (`a_toggle_undone_before_the_next_block_costs_nothing`,
  `coming_back_costs_the_latency_once_and_not_a_sample_more`), and the re-prime is held to zero
  allocations by `tests/rt_allocations.rs`.

Presets: the `[denoise]` table (see §8) selects level, channels and overrides. `Settings`
overrides (`noise_suppression`, `denoise_channels`) win over the preset when not `Preset`.

Shipped voice presets: `Laptop Mic` gains `[denoise] level = "medium"`; new files `Gaming
Headset.toml` (linked, medium, VAD gate), `Noisy Room.toml` (strong, mono), `Mechanical
Keyboard.toml` (strong, independent, fast gate); `Streaming` and `Podcast` gain a `[denoise]`
light row. Every shipped preset keeps `rnnoise = <level != Off>` so a 0.3.0 binary reads it.

## 4. `AudioProcessor`

`fxsound-dsp/src/input/processor.rs`:

```rust
pub struct ProcessContext { pub sample_rate: Real, pub channels: usize, pub voice_probability: Real }
pub trait AudioProcessor {
    fn prepare(&mut self, sample_rate: Real);         // redesign for a rate, then reset; never allocates
    fn apply(&mut self, params: &InputDspParams);     // each stage takes its own fields
    fn reset(&mut self);
    fn is_active(&self) -> bool;                       // switched on AND buildable at this rate
    fn latency_frames(&self) -> usize;                 // counted only while active
    fn process(&mut self, buffer: &mut [Real], ctx: &ProcessContext);
    fn meter(&self) -> StageMeter;                     // { reduction_db, running, aux }
}
pub enum Stage { Denoise(Denoiser), Dereverb(Dereverb), HighPass(HighPass), Gate(Gate),
                 Eq(EqStage), DeEsser(DeEsser), Compressor(Compressor), Makeup(Makeup),
                 Limiter(LookaheadLimiter) }           // implements AudioProcessor by match — no vtables, Debug stays
pub struct ChainSpec { stages: [Option<StageKind>; MAX_STAGES] }   // an ordering
impl ChainSpec { pub fn voice() -> Self; pub fn podcast() -> Self; pub fn broadcast() -> Self;
                 pub fn streaming() -> Self; pub fn custom(kinds: &[StageKind]) -> Self; pub fn by_name(&str) -> Option<Self> }
```

`InputChain` becomes `{ stages: [Option<Stage>; MAX_STAGES], sample_rate, power }` built from a
`ChainSpec` on the main loop; `process` walks the array; `apply(&InputDspParams)` fans out to
every stage (this replaces `InputEngine::apply_unconditionally` and the duplicate in
`tests/voice_presets.rs`); typed access `chain.stage::<Gate>()` keeps the existing getters
working. The limiter is always last and cannot be omitted by a spec. `InputEngine::new_with_spec`
exists; a voice preset may name its chain with `chain = "voice"|"podcast"|"broadcast"|"streaming"`
(default `voice`).

The gate takes `ctx.voice_probability`: with `vad_gate` on, a probability above 0.5 arms the hold
timer as an above-threshold level would.

## 6. Adaptive de-esser

`DeEsser::set_mode(DeEsserMode)`, `set_source_rate(Option<Real>)`, `realised_hz()`. In
`Adaptive` the corner is `min(requested, 0.25 · bandwidth)` where `bandwidth = min(fs,
source_rate)`; below 12 kHz of bandwidth the stage stands aside (there is no sibilance band).
The threshold is offset by `10·log10(bw_new / bw_requested)` so a wider relative band does not
trip earlier. `InputEngine::set_source_rate(Option<f32>)` is called by the audio crate from
`DeviceInfo::native_rate()` (`audio.rate` when published; a bluez5 headset profile → 16 kHz;
else `None` = the stream rate).

## 7. Echo cancellation, VAD, de-reverb

**AEC** = PipeWire's `libpipewire-module-echo-cancel` with `library.name = aec/libspa-aec-webrtc`,
loaded **into FxSound's own context** with `pw_context_load_module` (the one `unsafe` seam in the
audio crate; `#![forbid(unsafe_code)]` becomes `#![deny(unsafe_code)]` with a scoped allow in
`aec.rs` and a comment saying why). Module args:

```
library.name = aec/libspa-aec-webrtc
monitor.mode = true                             # far end = the real speakers' monitor, i.e. what is played after FxSound
capture.props  = { node.name = fxsound_aec_capture  node.link-group = fxsound target.object = <mic node.name> node.description = "FxSound echo capture" }
sink.props     = { node.name = fxsound_aec_monitor  node.link-group = fxsound target.object = <output lane target> stream.capture.sink = true }
source.props   = { node.name = fxsound_aec_source   node.link-group = fxsound node.description = "FxSound echo-cancelled" priority.session = 400 }
aec.args       = { webrtc.noise_suppression = false  webrtc.gain_control = false  webrtc.high_pass_filter = false  webrtc.voice_detection = false }
```

While AEC is on, the input lane's capture stream targets `fxsound_aec_source` instead of the
microphone; the module is (re)loaded when the microphone or the output target changes and
unloaded on `SetEchoCancel(false)`, on `DetachLane(Input)` and at exit. `AudioToUi::EchoCancel`
reports whether it is running; a missing `libspa-aec-webrtc` gives `running: false` with the
load error as `detail`, shown in the strip as `Echo  unavailable` — the same honesty rule the
de-esser follows. Our own `fxsound_aec_*` names join `OUR_NODE_NAMES` so they never appear as
devices.

**VAD**: RNNoise's voice probability (already computed) side-chains the gate (`vad_gate`).

**De-reverb**: `Dereverb` stage (`input/dereverb.rs`) — a late-reverberation suppressor in the
STFT domain (480-sample frames, hop 240, Hann, `realfft`): the late-reverb PSD is estimated as
`R(k,ℓ) = e^{−2·Δ·ln(1000)/T60} · |Y(k, ℓ−D)|²` with `D` = 50 ms and `T60` = 0.3 / 0.5 / 0.8 s
for Light / Medium / Strong, and a spectral gain `G = max(1 − R/|Y|², floor)` with `floor` = −10
/ −14 / −18 dB, smoothed over time. **Latency 480 frames**: the transform's own `N − H = 240`
plus the hop the block bridge adds — the same accounting as the denoiser's 960 (§2 & 3), and not
a choice. The first sample of an output hop is complete only once the whole *next* input hop is
in, so a constant lag under blocks of arbitrary size cannot be less than `2H − 1`; hop-aligned
processing could report 240, but the quantum is a power of two from 256 to 2048 and never a
multiple of the hop, so that figure was never what the signal lags by. Pinned by a
cross-correlation test, and held at every quantum the stream can deliver. It sits after the
denoiser and before the high-pass. Off unless a preset or the setting asks.

## 8. Calibration

RT side: `InputEngine` accumulates the pre-chain statistics listed in §1.2 and zeroes them on
`DspEvent::ResetCaptureStats`. The noise-floor estimator is a minimum tracker over 10 ms block
RMS in dB: falls instantly, rises at 0.5 dB/s, published always (it feeds the strip too).

GUI side: `CalibrationState { phase: Intro | Silence | Speech | Loud | Result, started: Instant,
floor_db, speech_rms_db, speech_peak_db, clipped_ratio, recommendation }` owned by `App`, driven
from `poll_audio`; each phase sends `ResetCaptureStats` on entry and reads the deltas on exit
(3 s / 5 s / 2 s). `Recommendation { preset: String, highpass_hz, gate_threshold_db,
compressor_threshold_db, makeup_db, ceiling_db, denoise: DenoiseLevel }` with:

- high-pass 80 Hz, or 120 Hz when the two lowest spectrum bands carry more than 30 % of the
  energy during silence;
- gate threshold = `clamp(floor + 8, floor + 4, speech_rms − 12)` dB (RMS detection);
- compressor threshold = `speech_rms − 6` dB, ratio 3;
- makeup = `−18 − (speech_rms − 4)` dB clamped to ±18 (target −18 dBFS RMS after ~4 dB of
  compression);
- ceiling −3 dB, or −6 dB when the loud phase clipped more than 0.1 % of samples;
- denoise: Off if floor < −60, Light if < −50, Medium if < −40, else Strong;
- recommended shipped preset: `Headset` if `speech_peak − speech_rms < 10` (close boom, low crest),
  `Laptop Mic` if floor > −45, `Clean Voice` otherwise.

**Apply** writes a user voice preset named `Calibrated — <device description>` (from the
recommended shipped preset with the numbers above) into the user Input store and selects it;
the record goes into `Settings.calibration`. `dialogs/calibration.rs` hosts the wizard like the
Import dialog; Settings ▸ Microphone ▸ `Calibrate microphone…` opens it (disabled when no
microphone is selected).

## 9. D-Bus

`crates/fxsound-app/src/dbus.rs`, zbus 5.19 `blocking-api` + `tokio` features (zbus is already in
the tree through ksni and notify-rust). Hosted on thread `fxsound-dbus`, session bus, names
`org.fxsound.FxSound` (the API) **and** `com.fxsound.FxSound` (the desktop-entry id, so shells
associate the window), object `/org/fxsound/FxSound`, interface `org.fxsound.FxSound`:

```
methods    TogglePower() → b, SetPower(b), NextPreset(), PrevPreset(), SetPreset(s), GetPreset() → s,
           SetOutput(s), SetInput(s), NextOutput(), NextInput(), SetNoiseSuppression(s), SetEditDirection(s),
           GetStatus() → s (the --status --json document), Show(), Hide(), ToggleWindow(), Quit()
properties Version (s, const), Power (b), Preset (s), Output (s), Input (s), Direction (s)
signals    PowerChanged(b), PresetChanged(s direction, s name), DeviceChanged(s direction, s node_name, s description),
           AudioStateChanged(s json), Notice(s message)
```

Every method builds the same `Vec<Command>` the CLI builds and sends a `Forwarded` over the
control channel the socket already uses, so there is exactly one execution path
(`commands::run`). `NameTaken` is logged and the app runs socket-only. The CLI stays on the
socket (it works without a session bus and forwards raw argv so parsing is single-sourced); the
D-Bus service is the public API for `busctl`, Waybar, Noctalia, KWin/GNOME scripts.

## 10. `--watch`

Socket subscription: `Request.watch: bool` (`#[serde(default)]`); the primary hands a watch
connection to a broadcaster instead of answering once, and every other connection now runs on
its own short thread with a 64 KiB line cap. Events are one JSON object per line, `{"v":1,
"event":..., "ts":<unix ms>, ...}`:

`status` (the full status document, on subscribe), `power {on}`, `preset_changed {direction,
name, modified}`, `device_changed {direction, node_name, description}` (`node_name` null =
detached), `devices_changed {count}`, `audio_state {direction, state: processing|idle|unavailable,
sample_rate, channels}`, `direction {direction}`, `input_meters {…}` (only with `--meters`, at
most 4 Hz), `notice {message}`, `window {visible}`, `quit`. Plain mode prints
`event key=value …`. `App::events: Vec<AppEvent>` + `drain_events()` is the single source; the
same events drive the D-Bus signals and replace the tray's per-tick fingerprint clone.

## 11. Bugs from the 0.3.0 audit fixed in 0.4.0

- `UiState.notification` had sixteen writers and no reader: the Pro view draws it as a bubble in
  the original's notification rect for four seconds; the Lite view as a strip under the combos.
- Preset selection by an unknown name (CLI / D-Bus) now fails instead of succeeding silently.
- The tray had no icon on any packaged install: status icons are shipped under
  `hicolor/*/status/` and the pixmaps are rasterised at start-up from the embedded SVG.
- Voice presets were read-only while the modified/save machinery still ran on them.
- Cross-direction leakage of master gain / filter width between a voice preset and the speakers.
- `Settings::load` reset everything on any parse error; `InputPreset::load_dir` dropped every
  preset on one bad file; `PresetStore` dedup missed a user preset named like a numbered factory
  one; two i18n tests raced on the global table.
- Six 0.3.0 microphone strings were untranslated in all 28 languages; a test now audits every
  `tr("…")` literal against the port tables.
- The audio-thread bugs listed in §1.3.

## 12. Idle CPU

- eframe 0.36.2 no longer busy-loops waiting for a redraw (upstream fix).
- The window's pump repaint is no longer unconditional at 10 Hz: producers (IPC, tray, signals,
  the engine's notification channel) wake the loop through a cloned `egui::Context`; the keepalive
  drops to 1 Hz.
- 60 Hz repaints only while the visualizer is unsettled *and* the meters changed *and* the Pro
  view is showing.
- Tray updates keyed on an event, not on a per-tick clone of every string.
- NODE 2 of the output lane sleeps while the sink has no clients (§1.3).
- `SpectrumAnalyser::push` skips a hop of pure silence; the compressor and gate skip `log10`/
  `powf` well below / above their thresholds.
- `theme::semibold()` / `bold()` no longer allocate a `FontFamily` per call.

## 13. Packaging and CI

- `fxsound --self-test [--json]`: version; factory `.fac` and voice TOML discovery and parsing
  from the install prefix; settings parse; an offline run of both chains (RNNoise instantiated);
  desktop file, icons (apps and status), systemd unit and man page present; runtime dir
  creatable; PipeWire and D-Bus reported `skip` when absent. Runs before the single-instance lock,
  so it works beside a running FxSound and in a bare container.
- `packages.yml` (reusable): archlinux (`makepkg` as an unprivileged user), debian:trixie,
  ubuntu:24.04 (`dpkg-buildpackage -b -d`, `apt install ./x.deb`), fedora:latest (`rpmbuild` with
  a vendored tarball, `dnf install`), tarball built on debian:bookworm's glibc and installed with
  its `install.sh`; each job then runs `fxsound --version`, `fxsound --self-test --json`,
  `desktop-file-validate`, counts the presets. `ci.yml` calls it; `release.yml` verifies that the
  tag matches every version stamp, calls it, and publishes every artefact plus `SHA256SUMS`.
- Packaging fixes: `PKGBUILD` gets `prepare()` (`cargo fetch --locked`) and honours a
  pre-set `RUSTUP_TOOLCHAIN`; `debian/rules` likewise; `build-tarball.sh` produces the same
  layout the release does and its `install.sh` rewrites the unit's paths for the prefix; the man
  page moves to `packaging/fxsound.1` and every package installs it; the `-bin` AUR recipe
  installs the TOML presets; `CHANGELOG.md` headings are real headings; `hicolor/*/status`
  icons ship everywhere.
