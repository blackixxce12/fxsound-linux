# «Как в Windows» / "Like FxSound for Windows" — the contract

This is the contract of the mode that brings FxSound for Linux back to the behaviour of FxSound for
Windows, set in **Settings ▸ Experimental** or with `fxsound --windows-parity`. The assignment table
below was approved by the user as it stands (28 September 2026). Every phase that builds a part
of the mode, and every new feature, works to it.

**0.5.0 offers three levels: Off, Interface, and Interface and sound.** Everything arrives in 0.6.0
(W4). Until then `full` is kept in the setting's enumeration, so that a file a later version wrote
still reads, but it is not on the slider, the command line and D-Bus refuse it with

> "Like FxSound for Windows" = Everything arrives in a later version of FxSound. This one offers
> off, interface and sound.

(`fxsound_core::parity::FULL_NOT_YET`, `--force` or not), and a `settings.toml` that says `full`
runs as `sound` and keeps `full` (§4.1). What this document says about Everything is the contract W4 builds to.

What exists at each phase:

| Phase | Version | What it builds |
|---|---|---|
| W0 | 0.5.0 | This contract; the setting, its option, D-Bus members, status keys and event; the Experimental tab and its slider of three positions; the classification of every command, tab and D-Bus call. **No level changes any behaviour yet.** |
| W1a–W1d | 0.5.0 | Interface and sound: the Windows DSP paths of the output lane, switched live. Since W1b Volume Leveling, Dynamic Boost and its limiter play them (`DspParams::compat`, `docs/0.5.0-dsp-inventory.md`); since W1c the equalizer's design below 20 Hz, Ambience with its slider, the gain stage and the balance, the Windows reading of a preset (by position, the Windows twenty-band ladder) and the unshifted export. Since W1d the level moves between the paths while something plays, over 20 ms and without a click, on the lane and on the applications' routes. |
| W2 | 0.5.0 | Interface: the Windows window (§2.3), with the Gilroy 0.4.0 embeds; the hooks later features ask their level through. |
| W3 | 0.5.0 | The command line and the tray at Interface. |
| W5 | 0.5.0 | Review and live check. |
| W4 | **0.6.0** | Everything: the port's own features hidden and stopped, live, and the confirmation in the window; the slider's fourth position. |

## 1. The levels

The levels are cumulative: each includes every level before it. Each is decided by **one rule**.

| Level | Key | Rule | Guarantee |
|---|---|---|---|
| Off | `off` | Nothing changes. | The output DSP renders bit-identically to `v0.4.0`, except the deliberate DSP changes of 0.5.0, each of them listed. |
| Interface | `interface` | A Windows feature the port **shows or operates** differently is set back to Windows: the look, the font (in 0.5.0 the Gilroy embedded as in 0.4.0; the Gilroy search and download are 0.6.0's, §2.2), the theme, the steps, the menus, the command line's window behaviour. The port's own features stay visible and working. | The DSP does not change. No setting is written. |
| Interface and sound | `sound` | Plus the Windows DSP paths of the output lane and of the applications' output routes. | Steady-state sound is bit-identical to `0f05ba5` (or below −120 dB), with the exceptions of §2. The same `.fac` sounds as it does on Windows. |
| Everything (**0.6.0**) | `full` | Plus the features **only this port has** are hidden and stopped: the microphone, the applications' presets, Customization, foreign preset formats, the port's own tray items. | Nothing is deleted. Going back restores the previous state live. |

**Never, at any level:** the port's fixes where Windows is wrong, behaviour that loses data, clicks on
transitions, platform necessities, and the Linux plumbing — the SNI tray, D-Bus, `--status`,
`--watch`, the keybind options, autostart, notifications. Through them a Linux desktop gets what
Windows has built in.

**The mode never writes the user's settings.** It is a view over them (`Effective`, W4): the level
is the one key it writes, and going back to Off finds every other setting as it was.

Three refinements of "bit-identical to `0f05ba5`":
- The transition fixes (#9, #10, #11 and the E6a dips) stay at every level. They do not change
  steady-state sound.
- For #39 and #44 the reference is the Windows C code, not `0f05ba5`, which had port errors there.
- The build it is held to is `3596e99`: `0f05ba5`'s engine and preset parser byte for byte, with the
  application that read a preset onto the user's band count as Windows does, by position.
  `0f05ba5`'s own application played every preset on the preset's band count.

Both guarantees are checked through the application's own reading of a preset
(`fxsound_dsp::preset::preset_params`) by `scripts/windows-parity-bitexact.sh`, against `v0.4.0`
for Off and, with `--compat=windows`, `3596e99` for Interface and sound. The Windows C code the
two exceptions are held to instead is compiled into golden vectors by
`scripts/windows-vectors/build.sh` (A2). `docs/0.5.0-dsp-inventory.md` lists every change to
the output lane's sound since `0f05ba5` and the level each one belongs to.

The level itself moves under a playing stream without a click (A4): what it changes glides or
crossfades over 20 ms, which the engine's unit tests hold on stereo and 5.1 against the tone
through either DSP, the allocation test holds to no allocation, and the click tests
(`crates/fxsound-audio/src/graph_churn/clicks.rs`) hold to −40 dBFS on the lane and on an
application's route. Every test of behaviour the audit changed on purpose has a twin that holds
the Windows behaviour at Interface and sound (A5); `crates/fxsound-dsp/tests/parity_pairs.rs`
lists the pairs and fails a change made on purpose that has none.

### 2.1 The port's own features

What Everything hides applies from 0.6.0 (W4), when Everything is offered.

- **Hidden and stopped at Everything:** the microphone lane, the voice chain, echo cancellation,
  calibration (a run in progress is cancelled), the voice presets, the applications' presets and
  their routes, the microphones' per-device presets, the tray's recording submenus, the in-app
  Changelog, the import of foreign formats.
- **Interface:** the tray's names cut at 30 characters, the tooltips on Windows features, the order
  of the language list (the order only, never the wrong names).
- **Auto-remembering a device's preset — Everything.** At Interface the port's features stay
  visible and working, and this one the user asked for. Where it is suppressed, **the map is still
  recorded, only the restore is suppressed**: the map "device → last preset" is kept at every level,
  so it is fresh on the way back to Off.
- **Never:** D-Bus, the command line, `--status`, `--watch`, `--self-test`, the SNI tray, "Follow the
  system's default device" (it also keeps the desktop's device switcher working), the trash, `.bak`,
  autosave, solo on Ctrl+Alt, the languages and translation fixes (Arabic and Persian stay
  right-to-left at every level), the per-device node volume (U10), mono outputs (U7), U12, U13, the
  E6a dips.

### 2.2 Features of later versions

Each new feature declares its level in its own phase, through the exhaustive classification of §3.
None of the features below is in 0.5.0: they are 0.6.0's (the Gilroy search and download, Manrope
and its type scale, MCP with `--diag`) and 0.7.0's (Customization, the visualizers, the rainbow,
glass, foreign preset formats, global shortcuts, `fxsound cava` / `fxcava`). In 0.5.0 the font is
the Gilroy embedded, as in 0.4.0, at every level.

- **Customization, the system palette, the visualizers, the rainbow, glass (0.7.0):** the Windows look at
  Interface and Interface and sound (FxSound's palette, the logo without animation, Spectrum only);
  at those levels the Customization tab is one line, "Disabled by «Like FxSound for Windows»", and
  the Reduced motion switch. The tab is hidden at Everything.
- **Foreign preset formats (0.7.0):** up to Interface and sound; hidden at Everything.
- **Global shortcuts (0.7.0), MCP and `--diag` (0.6.0), the click-free handover:** every level.
- **`fxsound cava` / `fxcava` (0.7.0):** independent of the level.
- **Gilroy (0.6.0):** at Interface and above, when a Gilroy is installed on the system or fetched
  with "Download Gilroy" (`fxsound --install-gilroy`: the three files of FxSound LLC's public
  repository, checked against pinned SHA-256, into `~/.local/share/fonts`). The Gilroy type scale
  is used only for the Gilroy 0.4.0 embedded, recognised by the checksum of its advance widths;
  any other Gilroy, and no Gilroy, gets Manrope's scale. Vietnamese keeps Manrope at every level.

## 3. Classification

`fxsound_core::parity::ParityClass` names the level at which a thing stops behaving as it does in
FxSound for Linux: `Interface`, `Sound`, `Full` or `Never`. Three classifications are exhaustive
`match`es with no `_` arm, so a new command, tab or D-Bus method does not compile until its level is
decided:

- **`Command::parity_class`** (`crates/fxsound-app/src/cli.rs`):
  - Interface — the options the Windows build has (`docs/COMMAND_LINE_OPTIONS.md`): `--power=0|1`,
    `--preset`, the preset management (#17, #18), `--output=DEVICE`, `--num_bands`,
    `--volume_leveling`, `--balance`, `--filter_q`, `--master_gain`, `--view`, `--language`, the band
    lists (#51) and `--set_effect`;
  - Full — `--input` and `--next-input`, `--edit`, `--noise-suppression`, `--app-preset`,
    `--app-input-preset`, `--list-apps` (it answers, with the applications hidden);
  - Never — the questions (`--status`, `--watch`, `--self-test`), the keybind options
    (`--toggle-power`, `--next-preset`, `--prev-preset`, `--next-output`), `--output=off`, the window
    options, `--forget-device`, `--quit`, `--windows-parity` itself, the way back, and
    `--export-unshifted`, a choice of the port's own that Interface and sound follows and no level
    hides.
- **`SettingsTab::parity_class`** (`crates/fxsound-ui/src/dialogs/settings.rs`): Audio, General,
  Help and Experimental never; Microphone and Applications at Everything. **Experimental is never
  hidden**: it is the way back. When the tab on show is hidden, Settings moves to Experimental.
- **`Call::parity_class`** (`crates/fxsound-app/src/dbus.rs`): `SetInput`, `NextInput`,
  `SetNoiseSuppression`, `SetEditDirection` and `SetAppPreset` refused at Everything, and
  `ListApps` at Everything too, but answering with the applications hidden, as `--list-apps` does,
  rather than refused; every other method never — D-Bus is Linux plumbing, and no method raises
  the window at any level.

## 4. The setting and its interfaces

### 4.1 `settings.toml`

- `windows_parity = "off" | "interface" | "sound" | "full"`, written only when it is not `off`.
- **Read without ever failing**, because a parse error moves the whole file aside and resets every
  setting: a string in any case (`everything` is `full`; in 0.5.0 `full` is kept as it was read
  and written back by every save, and runs as `sound` — `--status`, `--watch`, D-Bus, the slider
  and every behaviour of a level go by `sound` — until the user picks another level; picking
  `sound` itself changes nothing), `false` → `off`, `true` → `sound` (the
  superseded plan's single switch meant the Windows interface and sound together), anything else →
  `off`, with a warning in the log.
- `export_unshifted = true`, written only when set: the Export window's "Keep the end bands where
  they are" and `--export-unshifted`, followed from Interface and sound on (§2).
- **Keys this version does not know are kept** (`Settings::extra`) and written back as they were
  read, so a downgrade and an upgrade again lose nothing — a file with unknown keys survives a load
  and a save byte for byte. The one exception are the Windows keys nothing reads (0.4.0 audit #35:
  the five hotkey chords, `hotkeys`, `window_x`, `window_y`, `always_on_top`, `automatic_updates`,
  `last_update_time`, `device_configs_version`), which the next save still leaves out. 0.4.0 keeps
  nothing it does not know: after a downgrade to 0.4.0 its next save drops `windows_parity`.

### 4.2 The command line

- `--windows-parity=off|interface|sound` (any case; `--windows_parity`): a "set" option — it never
  raises the window, is honoured at a start, and is saved. It runs first on its line, so everything
  after it is done at the level it asks for. In 0.5.0 `full` (also `everything`) is read and
  refused with the text above, exit 1; the rest of the line is still carried out.
- `--force`, only with `--windows-parity`, for Everything: refused with it in 0.5.0.
- `--export-unshifted[=0|1]` (`--export_unshifted`; no value is 1): the Export window's choice of
  where the end bands go, saved; a "set" option that never raises the window. Followed from
  Interface and sound on; below it the choice waits and every export shifts.
- **At Interface and above (W3)** the command line and the tray are the Windows build's where §2
  says so:
  - R11: a line with an option the Windows build has (`Command::parity_class` = Interface) and
    nothing about the window raises the window, as step 11 of `applyConfig` does
    (`Cli::raises_like_windows`, `commands::run_forwarded`), at the level the line leaves in force;
    a start from one shows the window unless FxSound was last quit hidden
    (`Cli::only_sets_things_at`). The keybind options, the port's own options, `--quit` on the
    line and every D-Bus call, `Apply` included, never raise it.
  - #17 and #18: `--save_preset` on a preset with no unsaved changes is refused, with the way back
    named (`--windows-parity=off` saves a copy); the menu's Save New Preset waits for changes, and
    Export Presets and Import Presets wait for none (`App::preset_menu`).
  - #51: `--set_band_gain` and `--set_band_freq` set the pairs that fit — a band the equalizer has,
    a centre inside the band's range — and skip the rest, naming them in a note on stderr; the
    command succeeds. The Windows build drops a list with more pairs than bands whole; the
    approved row asks for the valid pairs, and that is what is done.
  - #31: the tray cuts a playback device's name after 30 characters, as `getTruncatedText(name,
    30)` does; the recording submenu, which only this port has, keeps the cut in the middle.
- **From 0.6.0, a move to Everything that would switch off something in use** — the microphone
  lane attached to a device, an application on a route of its own preset, a calibration in
  progress — **is refused** (exit 1) without `--force`: the window asks first, and a command line
  cannot ask. The text, the same on D-Bus and in MCP:

  > "Like FxSound for Windows" = Everything would switch off FxSound's microphone and application
  > presets now: programs recording through FxSound or playing through their own preset would move
  > straight to the devices. Your settings are kept. Add --force to switch anyway (force = true over
  > D-Bus).

- At Everything, from W4, a command or call for a hidden feature is refused with
  `hidden by "Like FxSound for Windows" = Everything; run fxsound --windows-parity=sound to bring it back`.

### 4.3 D-Bus

- Property `WindowsParity` (s, read-only, announced by `PropertiesChanged`).
- Method `SetWindowsParity(s level, b force)`: `--windows-parity=level`, with `force` as `--force`.
  A refusal is `org.fxsound.FxSound.Error.Refused` with the text above.

### 4.4 `--status --json` and `--watch`

- **Schema 3**, every key of schema 2 kept: `windows_parity` (`off` … `full`), `apps_hidden` and
  `input.hidden` (whether the level hides the applications' presets and the microphone lane, so a
  panel widget can grey its parts instead of failing). `--status` prints a `windows_parity:` line.
- `schema` is a compatibility number, not a version (the man page's STATUS DOCUMENT,
  *Compatibility*): adding a key never changes it; removing or renaming a key, or changing its
  meaning or JSON type, raises it, and a changed meaning gets a key of its own instead. 0.5.0 took
  the number from 2 to 3 along with the three keys above, as 0.4.0 took it from 1 to 2, before
  the rule was written down; it stays 3 from here on while keys are only added, and a release
  that only adds keys leaves it where it is.
- `gilroy: "installed" | "missing" | "not_used"` is added under schema 3 with the Gilroy search in
  0.6.0: until then there is nothing to report — 0.4.0's Gilroy is still embedded, and no level
  uses a font of its own. `theme_source` is added under schema 3 with the themes in 0.7.0. Neither
  changes the number.
- `--watch` event `windows_parity` with `level`: `{"v":1,"event":"windows_parity","ts":…,"level":"full"}`.

### 4.5 MCP (track M, 0.6.0)

The tool `set_windows_parity` takes `{"level": "off"|"interface"|"sound"|"full"}` and is marked
state-changing; the move to Everything is refused as above unless `confirm: true`. `get_status` and
`fxsound://status` carry the field, and at Everything the microphone and application tools return
the "hidden by" refusal as a tool error.

## 5. The Experimental tab

- **The tab:** after the port's other tabs — Audio, General, Help, Microphone, Applications,
  (Customization,) Experimental — with a flask icon drawn like the port's other nav icons.
- **Its caption:** a caption too long for one line is set in two, broken where the translation
  marks a long word with `{-}` («Эксперимен{-}тальное»; a hyphen is drawn at the end of the first
  line) or at a space, whichever sets it largest, in the `nav_caption` role, whose explicit line
  pitch keeps two lines inside the 40-point button with any face first in the chain. `tr` takes the
  mark out everywhere else. A soft hyphen (U+00AD) cannot do it: egui 0.36 neither breaks at one nor
  hides it.
- **The control:** a slider on `FxSlider` of three positions in 0.5.0 — Off, Interface, Interface
  and sound — and four from 0.6.0, whose positions sit over their labels;
  the chosen label is highlighted, and one line under the labels says what the position does. A
  drag is applied when it is let go, never at the positions it passes, and one cut short —
  Escape with the button held, Settings closed or hidden — applies nothing; a click on a position or its
  label, an arrow key, a wheel notch and a right-click (back to Off, as every slider resets) apply at
  once. Accessibility: a slider whose value text is the position's label and whose hint is the line.
  The tooltip (unless help tips are hidden) says what no level takes away.
- **The confirmation before Everything** (W4, 0.6.0): only when something in use would move, in
  the existing message box.
- Nothing else lives in the tab in 0.5.0 but "Smooth moves in WirePlumber" (roadmap §7, D5; §14
  #16 took it as an option, off by default), under the slider: a checkbox, the lines under it and
  "Restart WirePlumber" while a restart is due, which asks first — not once the box is back to what
  the WirePlumber running read (ticked and unticked again under it). It is at every level, as the
  tab is (class Never): it takes a click away and adds nothing Windows would not do, and "Always
  kept" names click-free switching. Its state is the hook's files in WirePlumber's directories,
  not a key of `settings.toml`, and it has no command-line option or D-Bus member
  (`fxsound_audio::wireplumber_hook`). "Download Gilroy" joins the tab in 0.6.0.
